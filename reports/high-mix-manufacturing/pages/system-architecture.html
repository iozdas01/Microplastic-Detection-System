Order to cut, end to end

The technical architecture for made-to-measure window coverings: two subsystems that meet at one schema, three agents that only run at setup, and a runtime that is entirely deterministic. Plus the equipment actually standing on a fabricator's floor, and what each machine will accept today.

Hand-authored 2026-09-03 · proposed design, not built · machine inventory and control types verified against vendor documentation · MHS read/write primitives and annotation layer per the 2026-08-27 announcement; no specification is public, so all MHS call syntax below is illustrative

01 · The seam

There are two products here, not one. Capture turns a window into an order. Fulfilment turns an order into a cut blind. They share exactly one interface, and nothing else — different users, different technology, different ways of failing.

02 · The whole system

Everything that runs at request time is deterministic. Every agent sits above the runtime, writing configuration that the runtime then executes without a model in the loop. Click any node for its specification.

03 · The objects

Six nouns carry the whole system. Every one is a plain document; nothing needs a graph database or a bespoke format.

  • runtime a new one per order, written by code
  • written by Agent A one per shop, written once at setup
  • phase 0 the spine
  • phase 1 the compiler
  • phase 2 capture
  • phase 3 machine handoff
  • phase 4 MHS · blocked on hardware

Each card carries two badges answering different questions. The first says who writes the document — deterministic code on every order, or an agent once at setup. The second says when it gets built, and section 08 has the reasoning. The cards below are ordered the way data moves through them, which is deliberately not the order they are built in — so the phase numbers run 2, 0, 1, 1, 3, 3, 4 as you read down.

Measurementruntimephase 2

What came back from the window. Never one number — a recess is not square, and checking that is exactly what a fitter does with a tape.

Produced by
Phone capture — ARKit / ARCore depth, LiDAR where present, photogrammetry with a printed fiducial where not
Key field
verdict — the trust envelope. A measurer that is right 95% of the time and cannot tell you which 5% is worse than sending someone
Ground truth
Laser distance meter. Free, non-destructive, infinitely repeatable

  "device":         "iPhone 15 Pro · LiDAR",

  "drop_mm":   { "left": 1652, "ctr": 1651, "right": 1649 },

  "confidence":  0.94,
  "threshold":   0.90,

  "photos":     ["…", "…"]

Orderruntimephase 0

The portable design intent, and the seam between the two subsystems. About twelve fields. This is a purchase order — no AI is required to produce or read it, which is precisely why it makes a good contract.

Loaded field
size_basis — recess means the fabricator applies the deduction and eats the remake; exact means the customer already did and owns the mistake. That single enum is where liability for a wrong measurement sits
Provenance
measurement_ref ties every order back to the capture it came from — without it you can never attribute a remake

FabricatorProfilewritten by Agent Aphase 1

The deduction table, structured. Today it lives in a spreadsheet, a laminated sheet taped to the machine, or one person's head — and it is different at every shop, for every system, for every fabric. This file is the compiler.

Versioned
Every CutList records which version compiled it, so a remake traced to a bad rule identifies every other order built on it
Provenance
The source line records where each rule came from — a document, an interview, or inference from past orders

04 · The transforms

Five functions. Four of them are pure.

TransformSignatureKindOwns
capturewindow → MeasurementML + thresholdAccuracy, and knowing when it is not accurate
specMeasurement + choices → OrderpureField validation, SKU existence
compileOrder + FabricatorProfile → CutListpureDeductions, allowances, refusal
emitCutList + MachineProfile → MachineJobpureFormat, units, machine limits
verifyMachineJob + read() → Actualphase 4Closing the loop
The rule the architecture turns on: agents write the configuration, deterministic code writes the numbers. compile() never calls a model. That is why a shop will accept output it did not calculate, why it can be unit-tested against their last thousand orders before go-live, and why a remake can be traced to one rule instead of a prompt.

05 · The three agents

None of them are in the happy path. Two run once and stop; the third only ever sees work the compiler refused.

Agent Asetuponce per fabricator

Onboarding a shop

Looks at
Their deduction spreadsheet · the laminated sheet taped to the machine · the system supplier's technical PDF · a stack of past order → cut-list pairs · an interview with the operator
Does not see
Live work orders. Machines. Anything at runtime
Writes
FabricatorProfile
Hard part
The edge cases nobody wrote down — which fabrics stretch, what exceeds the roll width, what cannot be railroaded because of a pattern
This is the MHS annotation layer, one for one: an agent interviews a human about knowledge that exists in no system, and emits a machine-readable reference file.
Agent Bsetuponce per machine model

Onboarding a machine

Looks at
The machine manual · its import file specification · one sample job file · photographs of the HMI screens
Writes
MachineProfile
Note

Agent Cruntime · rare

Exceptions

Looks at
An Order that compile() refused — width over the roll, SKU not stocked, no rule for this system × mount combination

Cut numbers. Not once, not ever

The finding in that table: the only genuinely MHS-ready machine on a blind fabricator's floor is the shutter router — and shutters are the one product that is not cut-to-length. Everything that makes the volume sits below the interface line MHS requires. Phases 0 through 3 therefore need none of it, and phase 4 waits on either a builder shipping native support or a retrofit box, which is a hardware company.

07 · What MHS adds, exactly

One object and two reads. It restructures nothing — it closes the far end of the loop and makes the profile maintain itself.

MHS is not how rework gets fixed. Rework is fixed by a deduction table and a phone camera. MHS is how the system eventually learns — every order becoming a labelled intent → machine → actual triple, generated as a by-product of trading.

08 · Order of build

Deliberately inverted from the obvious. The deterministic office work comes first, because it is cheap, it needs no training data, and it is the instrument that measures whether the expensive half is worth building.

  1. Phase 0 — the spine. The Order schema and an API. No AI. A weekend of work and everything else hangs off it.
  2. Phase 1 — the compiler. Agent A onboards a shop; compile() is deterministic from day one. Kills wrong deductions, transcription errors, wrong SKUs and missed fabric behaviour — four of the six sources of rework.
  3. Phase 2 — capture. The hard product, and the only one that needs ML. Build it once phase 1 has put you inside the fabricator with sight of their actual remake log.
  4. Phase 3 — machine handoff. Agent B maps formats; CSV or barcode into installed equipment. Removes the last retyping step. Boring, and it works today.
  5. Phase 4 — MHS. Read-back and stock discovery. Optional, blocked on hardware, and worth waiting for rather than forcing.

09 · What is load-bearing

The trust envelopephase 2

A measurement system that cannot report its own uncertainty converts a known cost — the visit — into an unknown one — the remake. verdict: send_a_human has to be a first-class, frequently-used outcome, not a failure state. Get this wrong and the product makes rework worse.

Profiles do not generalisephase 1

Every fabricator's deductions are different. That is the moat and the scaling tax in the same fact — each new shop is an onboarding, not a signup. Agent A exists to make that hours instead of weeks, which is the same arithmetic MHS is making on the machine side.

Fabric exclusivitycommercial

Many fabrics are tied to a specific supplier or brand. If a shop cannot legally make another shop's order, routing dies regardless of how good the compiler is. Unverified, and worth checking before anything is built.

The split is unknownopen question

Nobody yet knows what fraction of remakes start at the window versus in the office. That number decides whether capture or the compiler is the product — and it is obtainable from one question to anyone who fabricates.
