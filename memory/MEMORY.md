# Shared memory — versioned in git

One terse line per durable founder preference or process decision. Delete
stale lines on sight — git history preserves them. Never findings about the
idea; those live in `reports/`.

- Memory entries stay one-line terse; prune aggressively — context bloat is worse than lost nuance (2026-08-06).
- Workflow is quick-iteration, many-pivots: external strategy docs are decomposed into pipeline artifacts on arrival, never kept as living monolith context; don't demand a full pipeline pass per pivot (2026-08-06).
- Public X/Twitter content is a cross-idea publishing queue in `content/x/`, never per-idea state; drafts carry a `source:` pointer and are posted by hand, never by a skill (2026-08-09).
- Segment competence gate: ask a contact only about assumptions their role gives first-hand knowledge of. An out-of-competence answer enters the ledger as durable wrong evidence, and nothing downstream can tell it apart from a good one (2026-08-09).
- Assumption graphs hold ONLY market-testable claims (testable by talking to people); FMF nodes and technical build bets stay out — build gates live as kill conditions, run after demand is proven (2026-08-09).
- Assumption IDs are hunch-scoped: H{n}A{m}, H12A{m} for shared nodes; hunches number H1, H2… per idea. Flat A{n}/H00{n} IDs survive only in dated artifacts (2026-08-09).
- Research maps run in batches of 10 papers; a paper's METHOD is revealed behaviour and outranks what its authors say in an email. Map rows and outreach targets are different sets — screening happens separately (2026-08-08).
- Match reply length in outreach: a contact who writes short answers gets at most TWO questions per message. Hold the rest for the next round — a long list from a short correspondent gets one answer or none (2026-08-10).
- Check the historical precedent before accepting a "new" gap: find the field that hit it first (often decades back), why their fix stalled, and what they substituted instead — the stall reason is usually the real constraint (2026-08-09).
- Never publish a finding measured only on the cheap stand-in you scouted with: re-measure on the thing the claim is actually about before it leaves the repo. A scout-only result has been wrong by the full width of the conclusion (2026-08-11).
- Measure the channel the target system actually consumes, not the convenient proxy: the same input looked harmless on the easy metric and badly degraded on the one that mattered, and the conclusion inverted (2026-08-11).
- Check source licences before building any public asset: derived metrics and excerpts usually travel, but "ND" terms forbid republishing edited or derived media — normally the whole visual (2026-08-11).
- Every idea starts from a framework that names no vertical: market vocabulary an idea needs (value-chain layers, research axes, pain thresholds) is declared in that idea's own artifact frontmatter, never in `schemas/` and never in a generator (2026-08-19).
- ICP geography stays OPEN by default in every assumption's ICP fields — interview wherever reach exists; never pin a country unless the founder pins it (founder rule, 2026-08-20).
- Invite batches source 2nd-degree contacts first; 3rd-degree only when the 2nd-degree pool for the ICP is exhausted (founder rule, 2026-08-21).
- First invites NEVER carry copy — always a bare connection request, no note; first copy is the post-acceptance DM (LR-B29, founder rule, 2026-08-24).
- Claude may SEND a LinkedIn message only when the founder approved its exact logged text in chat, per-message, verbatim, with thread-name verification; approvals lapse on edit (copy-rules amendment, founder decision 2026-08-25).
- Re-contact decays with time, bought back only by position: silence under 3 months is a decision and seniority does not override it; a contact who REPLIED is a continuation, not a re-contact (LR-B30, founder rule, 2026-09-02).
- A contact list can pass every ICP check and still sample only the bottom of its market: band contacts by company size against that idea's own measured ladder BEFORE sending, and keep the band on the contact so per-band reply rates are comparable (2026-09-03).
