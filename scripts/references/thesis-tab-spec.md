# Thesis tab — rendering specification

Requirements for `render_thesis_tab()` in `scripts/build_control_room.py`. Read this
when extending that renderer; it is the spec, not a workflow.

This was `.claude/skills/startup-generate-dashboard/SKILL.md` until 2026-08-07, when the
skill was deleted. It had been superseded since 2026-08-06 and could not be correctly
invoked — the dashboard is generated by the script — but it still occupied a slot in the
skill index that every session loads. A specification is not a skill, and it belongs next
to the code it specifies.

The page is a pure projection of the markdown sources, so anything wrong on it is wrong in
a source file. Never hand-write `reports/control-room.html`: doing so silently destroys
the Contacts, Pain Patterns, Offerings and Company Intel tabs, and the founder usually does
not notice until the next outreach session.

---

Reads the current report files for a startup idea and produces a polished, self-contained HTML dashboard at `reports/control-room.html`.

This is a living artifact — it is always overwritten when called. Every time the ideation or assumptions work advances, the dashboard should reflect the current state.

**What's available drives what the dashboard shows:**
- Shotgun only → belief, hunch under test, public signals, component verdict,
  and recommended action
- Shotgun + lineage → active/proposed/retired hunch tree
- Shotgun + graph.md → full dashboard with hunch evolution + interactive assumptions matrix

## Step 4 — Build the dashboard prompt

Construct a detailed dashboard-building prompt. It must include:

1. **The raw content** from the shotgun report and graph.md, embedded verbatim
2. **The design requirements** (see Design System section below)
3. **The exact output path**: `reports/control-room.html`
4. **What to render** based on which files exist

Embed the actual data in the prompt — do not pass only file paths, because a delegated builder may not have enough context to interpret the schemas correctly.

---

## Step 5 — Build the dashboard

If a `ui-builder` agent is available, delegate the dashboard prompt:

```
Agent({
  subagent_type: "ui-builder",
  description: "Generate startup idea dashboard HTML",
  prompt: <your constructed prompt>,
  run_in_background: false
})
```

Wait for it to complete and verify that it wrote the file. If no `ui-builder` agent is available, execute the same prompt directly and write the self-contained HTML yourself. Agent availability must not block dashboard generation.

---

## Step 6 — Open in browser

After the dashboard is written:
```bash
open reports/control-room.html
```

Confirm to the user: "Dashboard written to `reports/control-room.html` and opened in your browser."

## Design System (pass this to the dashboard builder verbatim)

Include these exact requirements in the dashboard prompt:

### Core constraints
- Single HTML file, zero external dependencies — all CSS and JavaScript inline
- No CDN links, no external fonts, no image URLs — fully self-contained
- Overwrites any existing file at the output path

### Palette & feel
- Background: `#0d0f14`, cards: `rgba(24,27,36,0.72)` with `backdrop-filter: blur(14px)`
- Primary accent: `#6366f1` (indigo), secondary: `#8b5cf6` (violet), tertiary: `#06b6d4` (cyan)
- Text: `#f0f2f8` (primary), `#b4bcd0` (secondary), `#6b7490` (muted)
- Status colours: emerald `#10b981` (confirmed/high), amber `#f59e0b` (weak/medium), rose `#f43f5e` (against/low), slate `#64748b` (untested)
- Font stack: `"SF Pro Display", -apple-system, BlinkMacSystemFont, "Helvetica Neue", sans-serif`
- Hero animated blobs: three radial gradient orbs with different sizes and animation timings (20s/25s/30s), `filter: blur(90px)`, `opacity: 0.22`
- Dot grid overlay on hero: `radial-gradient(rgba(255,255,255,0.04) 1px, transparent 1px)`, `28px 28px`

### Navigation
Fixed top nav, `backdrop-filter: blur(24px)`, links to each available section (Belief, Field Map, Signals, Hunches, Contradictions, Assumptions, Next Test)

### Hero section
- Full-viewport height, blobs + dot grid in background, content at bottom
- Title: the idea name (`idea:` in `input-context/belief.md`), font-size `clamp(3rem,9vw,8rem)`, weight 800
- IQS score ring: SVG arc drawn via `stroke-dasharray/dashoffset` CSS transition on load — draw to `(score/10) * 283` pixels (283 = circumference of r=45 circle). If no IQS score in the shotgun, omit the ring.
- Methods counter: animate count from 0 to N using JS `requestAnimationFrame` with quartic ease-out
- Stable belief in a prominent italic callout below the hero

### Sections
Each section has a monospace label above the title, both in a container with `max-width: 1400px`, `padding-inline: clamp(1.5rem,5vw,4rem)`

**Belief and Current Hunch** — render the stable belief as the anchor and the active hunch as a distinct testable interpretation. Show belief status (`intact`, `under tension`, `at risk`) without visually treating a retired hunch as a dead belief.

**Public-Signal Evidence Matrix** — render evidence for and against the current
hunch with independent-source count, source types, communities/organizations,
recency, workaround evidence, counterevidence, out-of-scope alternatives, and
source limitations. Do not present votes or comment counts as market size.

**Hunch Decision and Lineage** — show the exact hunch tested, its component
verdict, recommended action (`retain`, `narrow`, `branch`, `retire`), and any
single proposed revision marked pending until founder confirmation. Render
parent/child/sibling relationships and status.

**Method Findings** — cards for root cause, job/substitutes, segment/wedge,
why-now/predecessors, and selected conditional methods. Preserve each method's
verdict on the same current hunch.

**Open Contradictions** — stacked tension cards with a split-panel layout: Side A vs Side B, each with coloured dot indicator, position text, and source chips. A cyan "What would settle it" bar below each card.

**Novel Angles** — stacked cards with a large background number (opacity 0.13), surfaced-by chip, title, and body text.

**Assumptions Matrix** (only if graph.md was provided):
- 4-column grid (3 on medium, 2 on small, 1 on mobile)
- Each card shows: ID badge, short label, category pill (colour-coded, see Category Colours below), kill power as filled/empty dots out of 5, test cost as filled/empty dots out of 5, confidence badge (emerald/amber/rose), status badge (emerald/amber/slate)
- On click: slide-in panel from the right edge (not a modal overlay), `width: min(560px, 100vw)`, smooth `transform: translateX()` transition
- Panel shows: full assumption text, why it matters, evidence for (green-tinted bullet list), evidence against (rose-tinted bullet list), next action (highlighted CTA box), parent/child assumption chips that navigate to that assumption when clicked
- ESC closes the panel, focus returns to the originating card
- Active assumption ID is tracked in a variable so clicking a chip navigates to the correct card and opens its panel

**Category colours** (for assumption pills):
- timing: indigo `#6366f1`
- pain: rose `#f43f5e`
- founder-market-fit: orange `#f97316`
- buyer: violet `#8b5cf6`
- technical: emerald `#10b981`
- trust: amber `#f59e0b`
- competition: pink `#ec4899`
- defensibility: teal `#14b8a6`
- market: indigo (same as timing)
- distribution: purple `#a855f7`

**Cheapest Next Test** — full-width card with an animated gradient border (background-size 300%, shifting keyframe). Shows the evidence most capable of killing the recommended hunch cheaply.

### Animations & interactions
- IntersectionObserver with `nth-child` stagger delays for reveal animations on scroll
- `cubic-bezier(0.16,1,0.3,1)` for all transitions
- Hover states: `translateY(-3px)` on cards, border brightens, subtle box-shadow
- Glass cards have a `::before` shimmer line at the top: `linear-gradient(90deg, transparent, rgba(255,255,255,0.1), transparent)`
- Custom scrollbar: 5px width, `#1f2330` thumb

### Accessibility
- All interactive elements have `aria-label`
- Assumption panel is a `role="dialog"` with `aria-modal="true"`
- Focus trapped inside open panel
- ESC closes panel and returns focus to originating card

## What to include in the dashboard prompt — data structure

When constructing the prompt, structure the embedded data clearly. For the ideation report, extract and label:

```
IDEA: {idea name}
DATE: {date from shotgun filename}
METHODS RUN: {count}
IQS SCORE: {extract if present; otherwise omit}
BELIEF: {founder-owned belief}
CURRENT HUNCH: {active hunch, if any}
BELIEF STATUS: {intact | under tension | at risk}

PUBLIC-SIGNAL EVIDENCE MATRIX:
{support, contradiction, uncertainty, alternatives, source limitations}

ROOT-CAUSE CHAIN:
{Five Whys native output}

JOB AND CURRENT SUBSTITUTES:
{JTBD/substitute output}

SEGMENT AND WEDGE:
{segment/wedge output}

WHY-NOW AND PREDECESSORS:
{timing output}

COMPONENT VERDICT:
{segment, problem, mechanism, why now, workaround, buyer}

HUNCH DECISION:
Action: {retain | narrow | branch | retire}
Recommended revision: {statement or none}
Founder confirmation: {pending | confirmed}

HUNCH LINEAGE:
{full lineage content when present}

METHOD FINDINGS: (as many as the report supports)
Theme 1: {title} | Sources: [...] | Summary: ... | Full detail: ...
...

OPEN CONTRADICTIONS: (3 contradictions)
Contradiction 1: {title}
  Side A ({label}): {position} | Sources: [...]
  Side B ({label}): {position} | Sources: [...]
  What settles it: ...
...

NOVEL ANGLES: (optional)
1. {title} | Surfaced by: {method} | Body: ...
...

CHEAPEST NEXT TEST: {paragraph}
```

For the assumption graph, include the full YAML for each assumption, clearly labelled:

```
ASSUMPTIONS GRAPH (13 assumptions):

--- A1 ---
id: A1
label: {short label — infer from assumption text if not present}
assumption: {full text}
category: {category}
kill_power: {N}
test_cost: {N}
confidence: {low|medium|high}
status: {untested|weakly_supported|confirmed}
quadrant: {quadrant}
why_it_matters: {text}
evidence_for:
  - {item}
  - {item}
evidence_against:
  - {item}
next_action: {text}
parents: [{A_IDs}]
children: [{A_IDs}]

--- A2 ---
...
```

Be exhaustive — every assumption field matters for the interactive panel.
